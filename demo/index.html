Recommendation Models

BookMind implements four distinct recommendation strategies, each with a different data source and algorithm.

📊

Popularity Model

src/popularity_model.py

How it works

Calculates a Bayesian weighted score per book using the average rating, the global catalog mean rating, and the log of the rating count. Books with both high quality and high volume are ranked highest.

Formula

score = (v/(v+m)) × R + (m/(v+m)) × C × log(v+1)

where R = average rating, C = catalog mean, v = number of ratings, m = minimum threshold

InputNone (global)
OutputSorted ranked list
Use caseCold-start
Artifactpopularity_model.pkl
Limitation: Does not capture individual user preferences. All users receive the same list.
🔍

Content-Based Model

src/content_model.py

How it works

Builds a TF-IDF matrix (up to 50,000 terms, bigrams) from book metadata — title, author, genres, description, language. Uses cosine-distance NearestNeighbors to find similar books. Enforces max 2 books per author for diversity.

Pipeline

Book Metadata→ TF-IDF→ NearestNeighbors→ Similarity Score
InputBook ID
OutputSimilar books + score
Use case"More like this"
Artifactcontent_model.pkl
Limitation: Depends on metadata quality. Less personalized than collaborative.
👥

Collaborative Filtering

src/collaborative_model.py

How it works

Builds a sparse user-item rating matrix and applies TruncatedSVD with 50 latent components. The user vector is dot-producted against all book vectors to produce a preference score. Books already rated are excluded.

Pipeline

User Ratings→ Sparse Matrix→ TruncatedSVD→ User·Book Score
InputUser ID
OutputRanked books + score
Use casePersonalized
Artifactcollaborative_model.pkl
Cold-start: Unknown users receive a popularity-based fallback with a clear label.
⚗️

Hybrid Ensemble

src/hybrid_model.py

How it works

Normalizes collaborative, content, readability, and popularity scores to [0, 1] then combines them with fixed weights. The content score is derived from the user's liked books (rated ≥ 4★) as a profile vector; the readability score matches book difficulty to the user's preferred reading level.

Model Evaluation

Evaluation uses a per-user holdout strategy: the last rated item per user is held out as the test item. Metrics are averaged across 500 users. Results are honest — not inflated.

Methodology

1
Holdout Split

Last rated item per user becomes the test item.

2
Train Inference

Models predict on remaining history.

3
Top-10 Cutoff

Top 10 recommendations are evaluated.

4
Average Metrics

Precision, Recall, NDCG, Hit Rate averaged across 500 users.

What these metrics mean

Precision@10

Of the 10 recommended books, how many were actually relevant (rated ≥ 4★ by the user in the holdout)?

Recall@10

Of all books the user actually liked, how many were captured in the top 10 recommendations?

NDCG@10

Normalized Discounted Cumulative Gain — accounts for the rank position of hits. Higher rank = more credit.

Hit Rate@10

What fraction of users had at least one relevant book in their top 10? A coarser but more forgiving metric.

Coverage

What fraction of the full book catalog appears in recommendations across all evaluated users?

On low scores: A precision of 0.001 in top-K on a catalog of 10,000 books with extremely sparse holdout data (each user has only one test item) is mathematically expected and is not an error. See the evaluation documentation for detailed discussion.
